1 产品概述

1.1 产品定位

面向单位内部食堂的轻量级点餐管理系统，通过"提前点餐 → 按需备餐 → 自动核销 → 费用结算"的闭环流程，解决食材浪费和费用核算不透明的问题。

1.2 产品目标

目标衡量指标目标值
减少食材浪费食堂剩余食材报废率降低 50% 以上
提高备餐精准度实际就餐人数 / 预估就餐人数≥ 95%
费用核算透明月度餐费对账耗时从 2 天降至 0.5 天
操作便捷员工完成点餐操作步骤≤ 3 步

1.3 用户角色与权限

角色权限范围数据可见性
普通员工点餐（增删改）、查询个人记录与统计仅本人数据
食堂管理员查看汇总、接单/关单、查询全员/部门/个人、结算打标、参数配置全员数据
系统管理员用户管理、部门管理、系统参数配置全员数据

3 功能模块详述——员工端

3.1 首页点餐 P0

页面描述

员工登录后进入首页，顶部显示月历组件用于选择日期（含未来日期提前点餐），下方展示选中日期的三餐卡片。每张卡片包含：餐次名称、开餐时间、套餐价格、当前状态、操作按钮。

日历组件

元素说明
月份导航左右箭头切换月份，显示“2026年10月”格式
日期网格7列日历网格，每天可点击选择；今天高亮，选中日期蓝色填充
点餐标注有已点餐记录的日期下方显示“X份”标签
非法定工作日法定节假日红色底标注名称或“休”；普通周末灰色底标注“休”；调休补班日（周六日上班）橙色标注“班”，正常可点餐
过去日期可点击查看历史记录，但不可点餐（置灰提示）
未来日期仅限工作日，可点击选择并提前点餐，截单状态根据该日期的开餐时间计算

字段定义

字段说明类型
餐次名称早餐 / 中餐 / 晚餐文本
开餐时间如 08:00、12:00、18:00（后台可配）时间
套餐价格如 ¥10、¥20、¥15（后台可配）金额
餐次状态可点餐 / 已截单 / 已接单 / 已关闭枚举
截单倒计时距截单剩余时间，格式"X小时Y分Z秒"文本
关闭原因当餐次被关闭时展示管理员填写的原因文本
操作按钮未截单时显示"点餐"/"取消"；已截单后置灰按钮

交互逻辑

  • 日历选择：默认选中今天，点击日期切换；切换月份后日历展示对应月份，选中日期不变
  • 初始状态：三餐卡片纵向排列，选中日期未到截单时间显示“可点餐”（绿色），操作按钮为“点餐”
  • 已点餐状态：卡片高亮，按钮变为“取消点餐”，同时显示已点餐标记
  • 截单倒计时：仅当选中日期为今天时显示实时倒计时；截单时刻到达后自动切换为“已截单”（橙色），按钮置灰
  • 未来日期：未到截单时间，状态为“可点餐”，可提前下单
  • 过去日期：显示“该日期已过”，仅供查看历史记录，不可操作
  • 已接单：管理员接单后，卡片显示“已接单”（绿色勾选标记），表示食堂将正常供餐
  • 已关闭：管理员关单后，卡片显示“已关闭”（红色），下方展示关闭原因文字，无需点击即可看到

业务规则

  • 同一员工同一餐次同一日期只能有一条有效记录；再次点餐为覆盖操作
  • 截单时刻到达后，前端按钮自动置灰，后端拒绝任何增删改请求
  • 餐次被关闭后，已点餐记录自动作废，不计入费用统计
  • 支持提前为未来日期点餐，每个日期的截单状态独立判断
  • 过去日期仅供查看，不可新增/修改/取消点餐

3.1b 一键批量点餐 P0

页面描述

员工可在首页日历下方一键为本周或本月所有工作日批量点餐，弹窗确认各餐份数后提交，避免逐日重复操作。

入口

日历组件下方显示两个按钮：「本周工作日点餐」「本月工作日点餐」。过去日期不显示。

弹窗内容

区域说明
日期范围显示覆盖的日期范围及工作日天数（如"9/15 至 9/19，共 5 个工作日"）
份数设置早/中/晚三餐各一行，含餐名、单价、开餐时间，右侧为份数步进器（0~10，0表示不点该餐）
预计合计实时计算：∑（每餐份数 × 单价）× 工作日天数
操作按钮取消 / 确认点餐

交互逻辑

  • 法定工作日定义：按国务院发布的法定节假日安排判断——排除法定节假日和普通周末，包含调休补班日；仅含当天及未来日期
  • "本周"：当前周的周一至周日中，>= 今天的日期（含补班日）
  • "本月"：当月所有日期中，>= 今天的日期（逐日判断法定工作日，含补班日）
  • 非法定工作日规则：节假日和普通周末食堂不开放，批量点餐自动排除，不生成任何记录；调休补班日（周六日上班）正常开放
  • 日期明细展示：弹窗中展示每个工作日的详细列表，含日期、星期、节假日名称、当天各餐已点餐情况和状态标签（可点餐/跳过）；过去日期标注"已过"，已截单/已关闭标注"已截单/已关闭"
  • 覆盖逻辑：仅对当天及未来且状态为"可点餐"的日期/餐次进行覆盖或新建；已点餐的覆盖更新份数，未点餐的创建新记录
  • 跳过规则（过去日期）：过去日期完全跳过，不创建、不覆盖、不删除已有记录
  • 跳过规则（已截单/已关闭）：当天或未来但已截单或已关闭的餐次自动跳过，不创建/不覆盖
  • 份数为0：该餐不点餐，不创建记录
  • 提交反馈：Toast提示成功条数，分别统计跳过天数（已过日期 + 已截单/已关闭条数）

3.2 我的记录 P0

页面描述

员工可按日期范围查询自己的点餐和用餐情况，查看统计汇总和明细清单。

页面布局

区域内容
筛选条件区起始日期（默认当天）、结束日期（默认当天）、查询按钮
统计汇总区4个统计卡片：点餐数量（份）、已结算费用（元）、未结算费用（元）、合计费用（元）
明细列表区表格展示：日期、餐次、价格、状态、结算状态；支持点击统计数字筛选对应明细

统计指标定义

指标计算口径
点餐数量所选日期范围内，状态为"已接单"或"已截单（待接单）"的记录条数
已结算费用所选日期范围内，结算状态为"已结算"且餐次未被关闭的记录费用之和
未结算费用所选日期范围内，结算状态为"未结算"且餐次未被关闭的记录费用之和
合计费用已结算费用 + 未结算费用

穿透交互

  • 点击"点餐数量"数字 → 筛选展示所有有效点餐明细
  • 点击"已结算费用"数字 → 筛选展示已结算记录明细
  • 点击"未结算费用"数字 → 筛选展示未结算记录明细
  • 点击"合计费用"数字 → 展示全部明细（恢复无筛选状态）

4 功能模块详述——管理端

4.1 运营看板 P0

页面描述

管理员登录后的首页，展示当日各餐次的点餐汇总和部门分布，支持接单/关单操作。

看板内容

区域内容
餐次汇总卡每个餐次一张卡片：餐名、开餐时间、截单时间、点餐总份数、状态（待接单/已接单/已关闭/食堂不开放）
份数明细条已接单/已关闭状态时，卡片内显示直观数据条：已接单份数（大字）、点餐人数（大字）、合计费用（大字），颜色区分状态（绿色=已接单，红色=已关闭）
部门分布表每个餐次下方展示按部门的点餐份数分布表，点击数字可穿透至该部门该餐次的明细清单
操作区每个餐次卡片提供"接单"和"关闭"两个操作按钮；关闭时弹出原因输入框；非工作日无操作按钮

接单/关单逻辑

  • 接单：点击"接单"按钮，餐次状态变为"已接单"，员工端同步显示
  • 关单：点击"关闭"按钮，弹出原因输入框（必填，支持预设模板如"点餐人数不足""食材供应问题""设备故障"等），提交后餐次状态变为"已关闭"，该餐次所有点餐记录作废，员工端展示关闭原因
  • 自动接单：距开餐前 M 小时（可配置，默认 M=2）管理员仍未操作接单或关单时，系统自动将餐次状态设为"已接单"，管理员仍可在开餐前撤销改为关闭
  • 时间约束：截单后方可执行接单/关单操作；截单前仅可查看，不可操作
  • 撤销：管理员可在截单后、开餐前撤销关单操作（改为接单），开餐后不可修改

5 业务规则与状态机

5.1 点餐记录状态机

可点餐（未截单） → 已截单（已锁定） → 已接单（手动/自动）
已截单（已锁定） → 已关闭（作废）
已接单（自动） → 已关闭（撤销自动接单） （开餐前管理员可撤销）
已接单 ↔ 已结算 / 未结算 （结算状态独立叠加，不影响主状态）

5.2 状态转换条件与操作权限

当前状态目标状态触发条件操作人可执行操作
可点餐可点餐员工修改/取消员工修改点餐 / 取消点餐
可点餐已截单截单时刻自动到达系统自动锁定，不可修改
已截单已接单（手动）管理员点击"接单"管理员记录有效，计入费用
已截单已接单（自动）距开餐前 M 小时（默认2小时）管理员未操作系统记录有效，计入费用；管理员可撤销
已截单已关闭管理员点击"关闭"并填写原因管理员记录作废，不计费用
已接单（手动/自动）已关闭管理员撤销接单改为关闭（开餐前）管理员记录作废，不计费用
已关闭已接单管理员撤销关闭改为接单（开餐前）管理员恢复记录有效
已接单已结算/未结算管理员打标操作管理员结算状态切换

5.3 截单时间计算

截单时间 = 开餐时间 - 截单时长（默认3小时） 示例（默认配置）： 早餐开餐 08:00 → 截单时间 05:00 中餐开餐 12:00 → 截单时间 09:00 晚餐开餐 18:00 → 截单时间 15:00 截单时刻到达后，系统自动将该餐次所有"可点餐"状态的记录变为"已截单"。

5.3.1 自动接单时间计算

自动接单时间 = 开餐时间 - 自动接单时长（默认2小时） 示例（默认配置：截单3小时，自动接单2小时）： 早餐开餐 08:00 → 截单时间 05:00 → 自动接单时间 06:00 中餐开餐 12:00 → 截单时间 09:00 → 自动接单时间 10:00 晚餐开餐 18:00 → 截单时间 15:00 → 自动接单时间 16:00 截单后至自动接单时间前，管理员可手动接单或关单。 自动接单时刻到达且管理员未操作时，系统自动将餐次状态设为"已接单"。 管理员仍可在开餐前撤销自动接单改为关单。 约束：自动接单时长 < 截单时长，即自动接单时间晚于截单时间。

5.4 非法定工作日规则

  • 法定工作日定义：按国务院发布的年度法定节假日安排判断，判断优先级为 调休补班日 > 法定节假日 > 普通周末：
    1. 日期在调休补班日列表中（如国庆前的周日补班）→ 是工作日，食堂开放
    2. 日期在法定节假日列表中（元旦、春节、清明、五一、端午、中秋、国庆）→ 非工作日，食堂不开放
    3. 日期为普通周六日 → 非工作日，食堂不开放
    4. 其余日期 → 工作日，食堂开放
  • 员工端展示：日历上法定节假日红色底并标注节假日名称（如"中秋"），普通周末灰色底标注"休"，调休补班日橙色标注"班"；选中非工作日时，三餐卡片状态显示节假日名称或"食堂不开放"，操作按钮置灰；一键批量点餐按钮隐藏
  • 管理端：当日为非工作日时，运营看板显示节假日名称或"非工作日"提示；各餐次状态显示"食堂不开放"，无接单/关闭操作
  • 批量点餐：getWorkdays() 逐日判断法定工作日，自动排除节假日和普通周末，自动包含调休补班日
  • 数据生成：系统不为非工作日生成餐次会话记录；查询统计结果中不出现非工作日数据
  • 日历维护：管理员可在系统配置中增删法定节假日（含名称）和调休补班日；年度新安排发布后由管理员更新，或对接官方日历数据源

5.5 费用计算规则

  • 单条记录费用 = 套餐价格（取下单时的价格快照，不受后续调价影响）
  • 已结算费用 = Σ（结算状态为"已结算"且非"已关闭"的记录费用）
  • 未结算费用 = Σ（结算状态为"未结算"且非"已关闭"的记录费用）
  • 合计费用 = 已结算费用 + 未结算费用
  • "已关闭"的记录费用为 0，不参与任何费用统计

用户(User) 1───* 点餐记录(Order) 部门(Department) 1───* 用户(User) 餐次配置(MealConfig) 1───* 点餐记录(Order) 餐次状态(MealSession) 1───* 点餐记录(Order)

idINTEGER PK主键

dept_idINTEGER FK所属部门

6.2.3 餐次配置表（meal_config）

字段类型说明
idINTEGER PK主键

6.2.4 餐次会话表（meal_session）

字段类型说明
idINTEGER PK主键
meal_dateDATE餐次日期
meal_typeVARCHAR(10)餐次类型
statusVARCHAR(20)open（待截单）/ locked（已截单）/ accepted（已接单）/ closed（已关闭）。其中 accepted 可由管理员手动触发或系统自动触发
auto_acceptedBOOLEAN是否为系统自动接单（true=自动，false=手动），用于区分接单来源
close_reasonVARCHAR(500)关闭原因（仅 closed 状态有值）
cutoff_atDATETIME截单时间
locked_atDATETIME实际锁定时间
accepted_atDATETIME接单时间
closed_atDATETIME关单时间
operatorVARCHAR(50)操作人

字段类型说明

meal_dateDATE餐次日期
meal_typeVARCHAR(10)餐次类型
priceDECIMAL(8,2)下单时价格快照
statusVARCHAR(20)active（有效）/ void（已关闭作废）

6.2.7 工作日历表（holiday_calendar）

存储法定节假日和调休补班日安排，用于判断食堂开放日期。每年国务院发布新安排后由管理员更新，或对接官方日历数据源自动同步。

字段类型说明
idINTEGER PK主键
calendar_dateDATE UNIQUE日期
day_typeVARCHAR(20)holiday（法定节假日）/ extra_workday（调休补班日）
holiday_nameVARCHAR(50)节假日名称，如"元旦""春节""国庆节"（补班日为空）
sourceVARCHAR(20)official（官方安排）/ manual（管理员手动维护）
created_atDATETIME创建时间

工作日判断逻辑：某日期为工作日 ⟺ （不在 holiday_calendar 中 day_type=holiday）且（不在 day_type=extra_workday 或为周一至周五）。

7 接口规范

7.1 员工端接口

GET /api/meals/today/ — 获取今日餐次列表

响应示例：

{ "code": 0, "data": [ { "meal_type": "breakfast", "meal_name": "早餐", "serve_time": "08:00", "price": 10.00, "status": "open", // open / locked / accepted / closed "close_reason": null, "cutoff_remaining": 7200, // 剩余秒数，已截单为0 "ordered": false // 当前用户是否已点餐 }, ... ] }
POST /api/orders/ — 创建点餐
参数类型说明
meal_typestring餐次：breakfast / lunch / dinner
meal_datestring餐次日期，支持当天及未来日期
quantityint份数，默认1，范围1~10

约束：截单后返回 403；同一餐次同一日期重复下单为覆盖操作；过去日期返回 403

DELETE /api/orders/{id}/ — 取消点餐

约束：截单后返回 403；仅可取消本人记录

POST /api/orders/batch/ — 批量点餐（一键工作日点餐）
参数类型说明
rangestringweek（本周工作日）/ month（本月工作日）
quantitiesobject各餐份数：{breakfast: 1, lunch: 1, dinner: 0}（0=不点）

响应：返回成功条数、跳过条数（已截单/已关闭）

约束：系统自动计算工作日范围（当天及未来），已截单/已关闭餐次跳过，已存在记录覆盖更新

GET /api/orders/my/ — 查询个人点餐记录
参数类型说明
start_datestring起始日期（必填）
end_datestring结束日期（必填）

响应：统计汇总 + 明细列表

7.2 管理端接口

GET /api/admin/dashboard/ — 运营看板数据

返回当日各餐次汇总 + 部门分布

PUT /api/admin/sessions/{id}/accept/ — 接单

将餐次会话状态改为 accepted

PUT /api/admin/sessions/{id}/close/ — 关单
参数类型说明
reasonstring关闭原因（必填）
GET /api/admin/orders/ — 查询点餐记录
参数类型说明
query_typestringuser / dept / all
user_idintquery_type=user 时必填
dept_idintquery_type=dept 时必填
start_datestring起始日期
end_datestring结束日期

响应：按维度的统计汇总 + 明细列表

PUT /api/admin/orders/settle/ — 结算打标
参数类型说明
order_idsarray点餐记录ID列表
settledbooltrue=已结算 / false=未结算
GET /api/admin/config/ — 获取配置

返回餐次时间、价格、截单时长、自动接单时间、关单原因模板

PUT /api/admin/config/ — 修改配置

修改餐次时间、价格、截单时长、自动接单时间等参数

GET /api/admin/calendar/ — 获取工作日历
参数类型说明
yearint年份（必填），返回该年所有节假日和补班日

响应：节假日列表（含名称）+ 补班日列表

POST /api/admin/calendar/ — 添加节假日/补班日
参数类型说明
calendar_datestring日期（必填）
day_typestringholiday（节假日）/ extra_workday（补班日）（必填）
holiday_namestring节假日名称（节假日必填，补班日可空）

约束：同一日期只能有一条记录；重复添加返回 409

DELETE /api/admin/calendar/{date}/ — 删除节假日/补班日

约束：删除后该日期恢复为默认周末/工作日判断；official 来源的记录删除需二次确认
