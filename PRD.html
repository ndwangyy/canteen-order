1 产品概述

1.1 产品定位

面向单位内部食堂的轻量级点餐管理系统，通过"提前点餐 → 按需备餐 → 自动核销 → 费用结算"的闭环流程，解决食材浪费和费用核算不透明的问题。

1.2 产品目标

目标衡量指标目标值
减少食材浪费食堂剩余食材报废率降低 50% 以上
提高备餐精准度实际就餐人数 / 预估就餐人数≥ 95%
费用核算透明月度餐费对账耗时从 2 天降至 0.5 天
操作便捷员工完成点餐操作步骤≤ 3 步

1.3 用户角色与权限

角色权限范围数据可见性进入方式
普通员工点餐（增删改）、查询个人记录与统计仅本人数据企微工作台，免登
食堂管理员查看汇总、接单/关单、查询全员/部门/个人、结算打标、参数配置全员数据企微工作台，免登
系统管理员用户管理、部门管理、系统参数配置全员数据企微工作台，免登

统一认证说明：全员通过企业微信进入系统。系统作为企微自建应用嵌入工作台，员工点击即打开H5页面，通过企微OAuth2自动完成登录鉴权（免账号密码），后端根据企微用户身份自动关联系统账号与角色。

3 功能模块详述——员工端

3.1 首页点餐 P0

页面描述

员工在企业微信工作台点击应用图标直接进入（企微OAuth2自动登录，无需输入账号密码），顶部显示月历组件用于选择日期（含未来日期提前点餐），下方展示选中日期的三餐卡片。每张卡片包含：餐次名称、开餐时间、套餐价格、当前状态、操作按钮。

日历组件

元素说明
月份导航左右箭头切换月份，显示“2026年10月”格式
日期网格7列日历网格，每天可点击选择；今天高亮，选中日期蓝色填充
点餐标注有已点餐记录的日期下方显示“X份”标签
非法定工作日法定节假日红色底标注名称或“休”；普通周末灰色底标注“休”；调休补班日（周六日上班）橙色标注“班”，正常可点餐
过去日期可点击查看历史记录，但不可点餐（置灰提示）
未来日期仅限工作日，可点击选择并提前点餐，截单状态根据该日期的开餐时间计算

字段定义

字段说明类型
餐次名称早餐 / 中餐 / 晚餐文本
开餐时间如 08:00、12:00、18:00（后台可配）时间
套餐价格如 ¥10、¥20、¥15（后台可配）金额
餐次状态可点餐 / 已截单 / 已接单 / 已关闭枚举
截单倒计时距截单剩余时间，格式"X小时Y分Z秒"文本
关闭原因当餐次被关闭时展示管理员填写的原因文本
操作按钮未截单且未点餐时显示"点餐"；已点餐后显示份数和金额（只读）+"取消点餐"按钮；已截单后置灰按钮

交互逻辑

  • 日历选择：默认选中今天，点击日期切换；切换月份后日历展示对应月份，选中日期不变
  • 初始状态：三餐卡片纵向排列，选中日期未到截单时间显示“可点餐”（绿色），操作按钮为“点餐”
  • 已点餐状态：卡片高亮，按钮变为“取消点餐”，同时显示已点餐标记
  • 截单倒计时：仅当选中日期为今天时显示实时倒计时；截单时刻到达后自动切换为“已截单”（橙色），按钮置灰
  • 未来日期：未到截单时间，状态为“可点餐”，可提前下单
  • 过去日期：显示“该日期已过”，仅供查看历史记录，不可操作
  • 已接单：管理员接单后，卡片显示“已接单”（绿色勾选标记），表示食堂将正常供餐
  • 已关闭：管理员关单后，卡片显示“已关闭”（红色），下方展示关闭原因文字，无需点击即可看到

业务规则

  • 同一员工同一餐次同一日期只能有一条有效记录；再次点餐为覆盖操作
  • 截单时刻到达后，前端按钮自动置灰，后端拒绝任何增删改请求
  • 餐次被关闭后，已点餐记录自动作废，不计入费用统计
  • 支持提前为未来日期点餐，但距今天数不得超过提前点餐上限（默认30天，后台可配）
  • 超出上限的日期不可点餐，日历置灰，提示"超出提前点餐上限"
  • 已点餐后份数和金额只读显示，取消后恢复可编辑状态
  • 过去日期仅供查看，不可新增/修改/取消点餐

3.1b 一键批量点餐 P0

页面描述

员工可在首页日历下方一键为本周或本月所有工作日批量点餐，弹窗确认各餐份数后提交，避免逐日重复操作。

入口

日历组件下方显示"一键点餐"按钮。过去日期、非工作日、超出提前点餐上限的日期不显示。

弹窗内容

区域说明
快捷范围选择本周 / 本月 / 10天 / 20天 / 30天（按钮动态生成，仅显示不超过提前点餐上限的选项）；自定义天数输入框（max=提前点餐上限）
日期范围显示覆盖的日期范围及工作日天数（如"9/15 至 9/19，共 5 个工作日"）；当天不纳入批量点餐范围，走单日流程
份数设置早/中/晚三餐各一行，含餐名、单价、开餐时间，右侧为份数步进器（0~10，0表示不点该餐）
预计合计实时计算：∑（每餐份数 × 当日单价）× 已选天数
操作按钮取消 / 确认点餐

交互逻辑

  • 法定工作日定义：按国务院发布的法定节假日安排判断——排除法定节假日和普通周末，包含调休补班日；仅含当天及未来日期
  • "本周"：当前周的周一至周日中，>= 今天的日期（含补班日）
  • "本月"：当月所有日期中，>= 今天的日期（逐日判断法定工作日，含补班日）
  • 非法定工作日规则：节假日和普通周末食堂不开放，批量点餐自动排除，不生成任何记录；调休补班日（周六日上班）正常开放
  • 日期明细展示：弹窗中展示每个工作日的详细列表，含日期、星期、节假日名称、当天各餐已点餐情况和状态标签（可点餐/跳过）；过去日期标注"已过"，已截单/已关闭标注"已截单/已关闭"
  • 覆盖逻辑：仅对当天及未来且状态为"可点餐"的日期/餐次进行覆盖或新建；已点餐的覆盖更新份数，未点餐的创建新记录
  • 跳过规则（过去日期）：过去日期完全跳过，不创建、不覆盖、不删除已有记录
  • 跳过规则（已截单/已关闭）：当天或未来但已截单或已关闭的餐次自动跳过，不创建/不覆盖
  • 份数为0：该餐不点餐，不创建记录
  • 提交反馈：Toast提示成功条数，分别统计跳过天数（已过日期 + 已截单/已关闭条数）

3.2 我的记录 P0

页面描述

员工可按日期范围查询自己的点餐和用餐情况，查看统计汇总和明细清单。

页面布局

区域内容
筛选条件区起始日期（默认当天）、结束日期（默认当天）、查询按钮
统计汇总区4个统计卡片：点餐数量（份）、已结算费用（元）、未结算费用（元）、合计费用（元）
明细列表区表格展示：日期、餐次、价格、状态、结算状态；支持点击统计数字筛选对应明细

统计指标定义

指标计算口径
点餐数量所选日期范围内，状态为"已接单"或"已截单（待接单）"的记录条数
已结算费用所选日期范围内，结算状态为"已结算"且餐次未被关闭的记录费用之和
未结算费用所选日期范围内，结算状态为"未结算"且餐次未被关闭的记录费用之和
合计费用已结算费用 + 未结算费用

穿透交互

  • 点击"点餐数量"数字 → 筛选展示所有有效点餐明细
  • 点击"已结算费用"数字 → 筛选展示已结算记录明细
  • 点击"未结算费用"数字 → 筛选展示未结算记录明细
  • 点击"合计费用"数字 → 展示全部明细（恢复无筛选状态）

4 功能模块详述——管理端

4.1 运营看板 P0

页面描述

管理员登录后的首页，展示当日各餐次的点餐汇总和部门分布，支持接单/关单操作。

看板内容

区域内容
餐次汇总卡每个餐次一张卡片：餐名、开餐时间、截单时间、点餐总份数、状态（待接单/已接单/已关闭/食堂不开放）
份数明细条已接单/已关闭状态时，卡片内显示直观数据条：已接单份数（大字）、点餐人数（大字）、合计费用（大字），颜色区分状态（绿色=已接单，红色=已关闭）
部门分布表每个餐次下方展示按部门的点餐份数分布表，点击数字可穿透至该部门该餐次的明细清单
操作区每个餐次卡片提供"提前接单"和"关闭（需填原因）"两个操作按钮（截单前和截单后均可操作）；关闭时弹出原因输入框；非工作日无操作按钮
当日调价每张餐次卡片下方显示当前单价和"调价"按钮；点击弹出调价弹窗，可设临时价格（仅影响当天新点餐，不影响历史和未来）；已设临时调价显示橙色"临时调价"标记，可一键恢复默认

接单/关单逻辑

  • 提前接单：截单前和截单后均可点击"提前接单"按钮，餐次状态变为"已接单"，员工端同步显示
  • 关单：截单前和截单后均可点击"关闭"按钮，弹出原因输入框（必填，支持预设模板如"点餐人数不足""食材供应问题""设备故障"等），提交后餐次状态变为"已关闭"，该餐次所有点餐记录作废，员工端展示关闭原因
  • 撤销关闭：截单前撤销关闭→恢复为可点餐状态（员工可继续点餐）；截单后撤销关闭→恢复为已接单状态
  • 关单通知（关键信息）：关单提交后，系统自动向当天已点餐员工发送通知，双通道并行：
    • 企微应用消息：实时推送至员工企微（免费），内容含餐次、关闭原因，员工点餐记录页面同步可见
    • 短信群发：向当天已点餐员工手机号群发（约3次/月×30人），确保未在线企微的员工也能收到
  • 月度结算通知（关键信息）：每月固定日（如1日）由定时任务触发，向全体员工发送上月餐费结算短信（点餐份数、合计费用、结算状态），100人×12月/年
  • 自动接单：距开餐前 M 小时（可配置，默认 M=2）管理员仍未操作接单或关单时，系统自动将餐次状态设为"已接单"，管理员仍可在开餐前撤销改为关闭
  • 时间约束：截单前和截单后均可执行接单/关单操作，管理员可提前操作无需等待截单
  • 撤销：管理员可在开餐前撤销关单操作；截单前撤销→恢复为可点餐，截单后撤销→恢复为已接单，开餐后不可修改

4.2 查询统计 P0

页面描述

管理员按用户、部门或全部维度查询点餐情况，支持穿透查询和结算打标。

查询维度

维度筛选条件结果展示
按用户查询选择指定用户 + 日期范围该用户的统计汇总 + 明细列表
按部门查询选择指定部门 + 日期范围部门汇总（含部门内各用户分布）+ 部门明细列表
全部部门查询仅选择日期范围各部门汇总对比表 + 全部明细列表

穿透查询逻辑

  • "按部门查询"结果中，各部门行展示点餐数量、已结算费用、未结算费用、合计；点击数字穿透至该部门对应明细
  • "全部部门查询"结果中，同上，每个部门一行；底部显示全员合计行
  • "按用户查询"结果中，统计区域数字可穿透至该用户对应明细
  • 穿透后的明细列表支持进一步按餐次、状态筛选

结算打标操作

操作说明
单条打标在明细列表中，每行右侧提供"已结算/未结算"切换按钮，点击即时更新
批量打标明细列表支持复选框勾选多条记录，点击"批量结算"或"批量取消结算"按钮
打标校验已关闭（关单）的餐次记录不可打标（因不计入费用）；仅"已接单"或"已截单待接单"状态可打标
实时更新打标操作后，统计汇总区域数字实时刷新

4.4 未结算报表 P0

页面描述

管理员可按日期范围生成未结算订单汇总报表，按员工统计，支持打印交财务对账。

入口

管理端侧边栏"未结算报表"。

筛选条件

字段说明
起始日期可空（空=从最早一条记录开始）
结束日期默认当天
生成报表按钮点击后按筛选条件查询并渲染报表
打印报表按钮点击后自动刷新数据并调用浏览器打印，打印时只显示报表区域

报表内容

区域内容

  • 不限定月初，随时可查，按日期范围筛选
  • 起始日期留空时，自动取最早一条记录的日期为起始
  • 打印时通过 @media print 隔离样式，只显示报表区域

5 业务规则与状态机

5.1 点餐记录状态机

可点餐（未截单） → 已截单（已锁定） → 已接单（手动/自动）
已截单（已锁定） → 已关闭（作废）
已接单（自动） → 已关闭（撤销自动接单） （开餐前管理员可撤销）
已接单 ↔ 已结算 / 未结算 （结算状态独立叠加，不影响主状态）

5.2 状态转换条件与操作权限

当前状态目标状态触发条件操作人可执行操作
可点餐可点餐员工修改/取消员工修改点餐 / 取消点餐
可点餐已截单截单时刻自动到达系统自动锁定，不可修改
已截单已接单（手动）管理员点击"接单"管理员记录有效，计入费用
已截单已接单（自动）距开餐前 M 小时（默认2小时）管理员未操作系统记录有效，计入费用；管理员可撤销
已截单已关闭管理员点击"关闭"并填写原因管理员记录作废，不计费用
已接单（手动/自动）已关闭管理员撤销接单改为关闭（开餐前）管理员记录作废，不计费用
已关闭已接单管理员撤销关闭改为接单（开餐前）管理员恢复记录有效
已接单已结算/未结算管理员打标操作管理员结算状态切换

5.3 截单时间计算

截单时间 = 开餐时间 - 截单时长（默认3小时） 示例（默认配置）： 早餐开餐 08:00 → 截单时间 05:00 中餐开餐 12:00 → 截单时间 09:00 晚餐开餐 18:00 → 截单时间 15:00 截单时刻到达后，系统自动将该餐次所有"可点餐"状态的记录变为"已截单"。

5.3.1 自动接单时间计算

自动接单时间 = 开餐时间 - 自动接单时长（默认2小时） 示例（默认配置：截单3小时，自动接单2小时）： 早餐开餐 08:00 → 截单时间 05:00 → 自动接单时间 06:00 中餐开餐 12:00 → 截单时间 09:00 → 自动接单时间 10:00 晚餐开餐 18:00 → 截单时间 15:00 → 自动接单时间 16:00 截单后至自动接单时间前，管理员可手动接单或关单。 自动接单时刻到达且管理员未操作时，系统自动将餐次状态设为"已接单"。 管理员仍可在开餐前撤销自动接单改为关单。 约束：自动接单时长 < 截单时长，即自动接单时间晚于截单时间。

5.4 非法定工作日规则

  • 法定工作日定义：按国务院发布的年度法定节假日安排判断，判断优先级为 调休补班日 > 法定节假日 > 普通周末：
    1. 日期在调休补班日列表中（如国庆前的周日补班）→ 是工作日，食堂开放
    2. 日期在法定节假日列表中（元旦、春节、清明、五一、端午、中秋、国庆）→ 非工作日，食堂不开放
    3. 日期为普通周六日 → 非工作日，食堂不开放
    4. 其余日期 → 工作日，食堂开放
  • 员工端展示：日历上法定节假日红色底并标注节假日名称（如"中秋"），普通周末灰色底标注"休"，调休补班日橙色标注"班"；选中非工作日时，三餐卡片状态显示节假日名称或"食堂不开放"，操作按钮置灰；一键批量点餐按钮隐藏
  • 管理端：当日为非工作日时，运营看板显示节假日名称或"非工作日"提示；各餐次状态显示"食堂不开放"，无接单/关闭操作
  • 批量点餐：getWorkdays() 逐日判断法定工作日，自动排除节假日和普通周末，自动包含调休补班日
  • 数据生成：系统不为非工作日生成餐次会话记录；查询统计结果中不出现非工作日数据
  • 日历维护：管理员可在系统配置中增删法定节假日（含名称）和调休补班日；年度新安排发布后由管理员更新，或对接官方日历数据源

5.5 费用计算规则

  • 单条记录费用 = 下单时价格快照（取下单时的实际价格，含临时调价，不受后续调价影响）
  • 取价逻辑：getMealPrice(type, date) → 优先读取临时调价（dayPriceOverrides），其次读取系统默认价格（meal_config.price）
  • 临时调价仅影响调价后的新点餐，不影响已有订单的费用快照
  • 已结算费用 = Σ（结算状态为"已结算"且非"已关闭"的记录费用）
  • 未结算费用 = Σ（结算状态为"未结算"且非"已关闭"的记录费用）
  • 合计费用 = 已结算费用 + 未结算费用
  • "已关闭"的记录费用为 0，不参与任何费用统计

7 接口规范

7.0 统一认证（企业微信免登）

GET /api/auth/wecom/callback/ — 企微OAuth2免登回调

员工从企微工作台进入应用，企微携带授权码 code 回调本接口；后端通过企微API以 code 换取用户身份（userid），自动关联/创建系统账号并按角色返回界面，全程免账号密码。

参数类型说明
codestring企微OAuth2授权码（企微自动携带）
statestring防CSRF随机串（企微自动携带）

响应：会话Token + 用户信息（姓名、部门、角色），前端据此渲染员工端或管理端

前置配置：企微管理后台创建自建应用，配置可信域名、OAuth2回调地址、可见范围（全员）
